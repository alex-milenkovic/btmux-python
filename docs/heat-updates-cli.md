# Heat and per-tick simulation interface

This interface exposes the heat and per-tick production services. Input fields,
command results and named dice streams distinguish ordinary gameplay from
explicit diagnostic operations. Decoder, session and observation adapters
remain in `tools/`; command and gameplay rules use the functional owners.

Run `python3 -m tools.heat_updates --input ./tmp/workflow.json`; `--help` describes
entry points and limits. The command emits one JSON document on success.
Rejected pilot commands are successful workflows with `accepted: false`.
Unknown fields/enums, invalid physical slots, inconsistent capacity, duplicate
JSON keys, unsupported profiles and exhausted supplied dice streams are errors:
nonzero exit, stderr diagnostic, no success document. The simulation interface
contains diagnostic state/maintenance operations; gameplay commands call the
existing production systems. It does not implement the independent QA suite.

## Input

Root fields: `map`, `units`, `config`, `clock`, `random`, `actions`; only `actions`
is required. Units default to one ready 50-ton biped named `u`, at `[2,2,0]`,
capacity 10, no disabled sinks, weapon/engine heat or mounted weapons, piloting 5,
100 armor/internal per section, and no injuries. All clocks default to zero.
Map defaults to clear 8x8, elevation zero, 25 C, gravity 100.

`map`: `size: [width,height]`, `default: [terrain,stored_elevation]`,
`hexes: [{at:[x,y],terrain,elevation}]`, `temperature`, `gravity`,
`special_rules`, `visibility`, `light`, `bridge_protection`. Terrain names are
those of the movement interface (including WATER, ICE, BRIDGE, FIRE and SMOKE).
Stored elevation is nonnegative 0..9; unit Z is signed. Underlays use
`underlying: [{at:[x,y],terrain,remaining:120}]`; the visible hex must already
be FIRE/SMOKE, and underlying terrain must be real terrain. The supplied
remaining lifetime expires this fixture overlay; it does not implement fire
spreading. Smoke generated by water extinguishing uses the production expiry.

Each `units` entry supports these movement fields:
`name` (or existing `id`), `class`, `movement`, `at:[x,y,z]`, `fz`, `tons`,
`actual_tons`, `max_speed`, `speed`, `desired_speed`, `vertical_speed`, `facing`,
`desired_facing`, `jump_mp`, `fuel`, `free_fuel`, `pilot_skill`,
`pilot_skill_base`, `pilot_id`, `caller_id`, `wizard`, `pilot_hits`, `team`,
`cocoon`, `lateral`, `states`, `advantages`, `relative_position`, `altitude`,
`target_id`, `target_hex`, `load`, `turret`, `auto_turret`, `started`,
`conscious`, `blinded`, `fallen`, `consistent`, `map_valid`, `pain_resistance`,
`searchlight`. The last two are optional booleans (default false); pain resistance
requires a pilot. Section component conditions retain the movement interface's
lowercase `working`, `disabled`, `destroyed` values.
Existing movement enum/relative-position/load/section decoding is reused.
`states` defaults to started; explicit boolean fields override those flags.
`states: ["in_character"]` enables the C pilot-only identity gate. A false
`consistent` is an invalid fixture; `map_valid:false` removes the command's map.
`turret` accepts `present`, `jammed`, `locked`, `facing`. A unit target ID is a
unit name in this document; it takes precedence over `target_hex:[x,y]`.

`heat_state`: `heat`, `plus_heat`, `weapon_heat`, `engine_heat`,
`sink_technology: SINGLE|DOUBLE|CLAN`, `sink_capacity`, `disabled_capacity`,
`cutoff`, `leg_sink_slots`, `last_overheat_tick`, `life_support_destroyed`,
`stealth`, `null_signature`. Capacity and disabled capacity are dissipation
units. Double/Clan total capacity must be even. Functional leg-sink slots are
installed as actual components and cannot exceed supplied physical capacity.
Map special rules initialize the unit's special-environment flags.

`sections` uses the existing movement format:
`[{location:"LTORSO",front:100,rear:100,internal:100,recycle:0,...}]`.
Optional original values, base-to-hit, flooded state and movement component
fixtures use the existing decoder. Section names for equipment/actions are
`CT/LT/RT/LA/RA/LL/RL/HD` or `Location` names for mechs, and `VehicleLocation`
names for vehicles (`FRONT`, `REAR`, `LSIDE`, `RSIDE`, `TURRET`, `ROTOR`).

`equipment` is an ordered list; list index is mounted weapon number:
`[{name:"AC",category:"BALLISTIC",damage:10,ammo_per_ton:10,
section:"RA",slot:5,recycle:0,temporary_failure:"NONE"}]`.
Categories: ENERGY, BALLISTIC, MISSILE, ARTILLERY, HAND. `salvo` is the full-salvo
entry (default 1); `table_match:false` explicitly models no matching C missile
entry. `temporary_failure` is NONE, TEMPORARY or DESTROYED. Ammo weapons require
positive `ammo_per_ton`. Slots are one-based and constrained by class/location.
The optional boolean `fired_rocket` (default false) sets the production
ROCKET_FIRED part mode for recycle-message diagnostics.
`bins: [{weapon:0,section:"LT",slot:1,rounds:3,condition:"FUNCTIONAL",inferno:false}]` references
mounted weapon numbers. Conditions: FUNCTIONAL, BROKEN, DESTROYED, DISABLED.
`inferno:true` requires a missile weapon and sets the production bin ammo mode.
Overlapping equipment/bin slots are rejected. These are input metadata, never
expected outcomes.

`history: [{amount:20,wall:0,counted:false}]` is chronological whole-hit history.
`last_stagger_check`, `stagger_stamp` (-1 or 0..29) and `last_dropship_notice`
are optional unit fields. `events` accepts `inferno:<remaining seconds>`,
`burns:[{section:"FRONT",remaining:60}]`, `extinguish:<remaining seconds>`,
`cutoff:{remaining:4,engage:true}`. Deadlines must be positive remaining times.
These seed real events without applying a fictional initial attack.

`config`: `periodic_updates:true`, `heartbeat:true`,
`advanced_vehicle_fire:false`, `new_stagger:1` (0/1/2), `stagger_interval:5`,
`stagger_tonnage:true`, `heatcutoff_enabled:true`, `movement_modes:true`,
`mw3stats:false`, `inferno_penalty:false`. The latter enables the existing C
inferno-ammunition avoidance/retained-heat option for this session. Alternate
compile profiles are rejected. `mw3stats:false` selects the ordinary fixed-target
shutdown rule for every pilot, including AUTO controllers; it does not select
the historical below-14 shutdown fallthrough. No Computer-skill override is
implemented.

The shared overheat/ammunition routine is eligible at heat 10 when at least
30 event ticks have elapsed since its last check. It records that tick, checks
ammunition first, and evaluates shutdown against the live state afterward.
Below 14 heat there is no heat shutdown or shutdown-avoidance draw. At
14/18/22/26, ordinary 2d6 must meet 4/6/8/10 until the next threshold; at 30+
shutdown is automatic with no shutdown draw. Fractional heat is compared
without rounding. `shutdown_rolls:[]` is valid below 14 and at 30+; due
`ammo_avoidance` draws can still occur, including inferno checks at 10..13.9.

`clock`: `wall`, `event`, `heartbeat`, `last_dispatch`. Wall and event clocks
are separate; the existing catch-up clamp and wall-modulo cadence are preserved.
Normal advance runs dispatch and (if enabled) heartbeat each second. `dispatch`
runs successive dispatch seconds without heartbeat. `heartbeat` adds only the
requested wall seconds and invokes one heartbeat, leaving event time unchanged.
A later dispatch sees the accumulated wall-time backlog, as in the real engine.

`random`: optional `seed` (default 0) and named finite integer arrays:
`pilot_rolls`, `fall_pilot_rolls`, `critical_rolls`, `attack_rolls`, `ammo_avoidance`, `shutdown_rolls`, `fire_rolls`, `motive_rolls`
and `hit_location_rolls` are 2..12; `fire_damage` and `fall_directions` are 1..6;
`heat_injury` is 0/1; `dump_candidates` is a zero-based candidate index validated
against the actual selected stream. Omitted streams use the seeded generator;
an explicitly supplied stream errors on exhaustion. Draws occur only when the
production rule asks and are recorded in order. `critical_rolls` controls the
internal-damage critical table, including gravity limb damage. Fall injury
piloting uses `fall_pilot_rolls` and observations with source `fall`, separately
from the stability/stagger roll that caused the fall.

## Actions and output

- `command`: `unit`, `name`, `args` (array of strings). New commands are
  `heatcutoff`, `dump`, `extinguish`, `startup`, `target <unit-name>`, `fire <weapon-number>`;
  existing speed, vertical, jump, prone, shutdown and turret commands remain.
- `advance` or `dispatch`: `seconds` (0..10000).
- `scan`: `unit`. Refreshes production map LOS geometry and arms the existing
  PLOS acquisition event. Advance time to acquire contacts before firing.
  `fire` invokes the real command-level targeting/LOS/arc/weapon gates, resolves
  actual damage, and applies heat/ammunition/recycle effects. `attack_rolls`
  supplies the actual 2d6 attack roll; it does not force an accepted shot or hit.
- `heartbeat`: `wall_seconds` (0..10000).
- `inspect`: optional `unit`; read-only snapshots consume no dice.
- `hit`: `target`, optional `attacker`, `section`, `arc:FRONT|REAR`, `damage`,
  `weapon` (mounted number on attacker, or null for nonweapon/internal effects).
  Uses normal armor/internal transfer; null weapon prevents dumping ignition.
- `external_heat`: `unit`, optional `attacker`, `heat`, `inferno` boolean.
- `enter_hex`: `unit`, `at:[x,y,z]`, optional `fallen`. Installs the explicit
  destination, then executes real terrain-entry and height consequences;
  it is a diagnostic movement affordance, not a replacement movement engine.
- `maintain`: `unit`, `kind`: heat, overheat, pilot, height, stagger_totals,
  stagger_expiry, dropship_notice, water_extinguish. These call actual production
  boundaries. `water_extinguish` calls only production `water_extinguish_inferno`
  using the current terrain/depth/Z, without movement settling. `enter_hex`
  retains full movement settling before its terrain-entry consequences.
- `stagger`: `unit`, `action:MARK|REMOVE|CLEAR_ALL`, `level` (nonnegative).

Output includes `initial`, `final`, ordered `results`, `draws`, `consumed`.
Each result includes notifications, resolved rolls, damage observations and an
actual state snapshot. Snapshots expose clocks, heat balance, retained heat,
sink capacity, cutoff/dump/fire/inferno deadlines, ammo rounds, real steam
underlay/lifetime, section damage, injuries, stagger nodes/totals, posture,
coordinates, speeds, facings, kill reason, turret LOS and recycle/temp failure.
Inactive deadlines are null. Notifications/damage carry an action/event source.
Nested secondary hits are separate observations; do not sum the outer hit's
before/after delta and its nested ignition record as two independent totals.

Any unavailable external delegates are listed explicitly in `unavailable`;
they are not reported as successful checks.

## Runnable examples

Save each document under `./tmp/` and pass its filename to `--input`.

```json
{"units":[{"name":"u","heat_state":{"heat":100,"plus_heat":20,"weapon_heat":20,"sink_capacity":10,"disabled_capacity":0}}],"actions":[{"op":"advance","seconds":2},{"op":"inspect"}]}
```

```json
{"config":{"periodic_updates":false},"units":[{"name":"u","equipment":[{"name":"AC","category":"BALLISTIC","damage":10,"ammo_per_ton":5,"section":"RA","slot":5}],"bins":[{"weapon":0,"section":"LT","slot":1,"rounds":3}]}],"actions":[{"op":"command","unit":"u","name":"dump","args":["all"]},{"op":"advance","seconds":6},{"op":"inspect"}]}
```
